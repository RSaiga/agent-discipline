# cycle — リストが尽きるまで回す / Run the loop until the list is done

`accept.md`・`red.md`・`green.md`・`refactor.md`・`commit.md` を、決まった順に実行する。段階の境界は越えるが、各段階の規律は緩めない。
単層のリストなら内側のループだけ、二重ループのリストならシナリオごとに外側と内側を回す。
Runs the stage procedures in order. Crosses stage boundaries only; every stage keeps its rules.

**コミット:** `config.yaml` の `commit` が `on-request` なら、この入口を呼んだことがコミットの依頼にあたる。`never` なら、コミットの段階では
コミットせず、ステージするファイルとメッセージの案を報告に残して**先へ進む**（止まらない）。
With `commit: never`, commit steps record a proposal in the report and the loop continues.

**判断に迷ったら止まる方を選ぶ。** 回しきることは目的ではない。 / When in doubt, stop.

## 始める前 / Before the loop

最初の往復で、`discipline.md`・`tdd.md`・この手順・各段階の手順と設定をまとめて読む（`discipline.md` の「まとめて行う」）。
次の往復で、リストと `tdd.rules` の規約を読み、`git status` を見る。どれもループの中で読み直さない。

1. **リストを確かめる**（`tdd.md`「テストのリスト」）。無い・書けない → 止まる。全部終わっている → 緑を確かめて「完了」と伝えて止まる。
2. **最初が緑であることを確かめる。** リストが触る範囲の `fast` のスイートを全体で走らせる。`tdd.known_failures` に名前のある失敗だけを除き、
   それ以外が落ちていれば、何が落ちているかを報告して**止まる**（直すのはこのループの仕事ではない）。
   作業と関係のない差分が作業ツリーにあれば、それも報告して止まる。
   `speed` の無いスイートもここで全体を走らせ、かかった時間で決める（1 分以内なら `fast`）。決めた値は 3 の宣言に書き、`profile.md` は書き換えない。
   Start green: run the fast suites; anything failing that is not a named known failure means stop.
   A suite without `speed` runs here too; its time decides it (within a minute is fast), stated in the declaration, not written to the profile.
3. **走らせ方を 1 行で宣言する**（どのスイートを毎回全体で、どれを絞って走らせるか。二重ループなら、外側はスタックを動かしたまま 1 本ずつ）。
   ループの中ではそれに従い、測り直さない。

## 内側のループ / The inner loop

項目ごとに、未着手が無くなるまで（二重ループでは、進行中のシナリオの内側が尽きるまで）:

1. **red** — `red.md`。
2. **green** — `green.md`。
3. **コミット（振る舞い）** — `commit.md`。`feat` か `fix`。直前の green の結果を緑の確かめに使い、`slow` の全体はループのあとで 1 回にする。
4. **refactor** — `refactor.md`。直すものが無ければ何もしない。
5. **コミット（リファクタ）** — 4 で変えたときだけ。`refactor`。空のコミットを作らない。
6. **次の項目へ。** 前の項目の気づきを持ち越さない。

単層のリストは、これをリストが尽きるまで回して「抜けたら」へ進む。

## 二重ループ / The double loop

シナリオを**1 本ずつ**、上から順に回す。シナリオをまとめて処理しない。

1. **外側を書いて落とす** — `accept.md` の A。シナリオを進行中のタグ付きで書き、振る舞いで落ちるのを見て `[~]` にする。
   書いたシナリオ（と step・補助）を `test` の 1 コミットにする（進行中のタグは既定の実行から外れるので、全体は緑のまま）。
2. **最初の通り道なら** — `green.md` の最初の通り道。外側の 1 本だけで全部の層を最も薄くつなぐ。内側のテストは書かない。
   緑になったら `feat` の 1 コミット。直すものがあれば `refactor.md` で直して `refactor` の 1 コミット。3 へ。
   **それ以外なら** — 内側のループを、このシナリオの内側が尽きるまで回す。3 へ。
3. **外側を走らせる** — `accept.md` の B。
   - 赤: 最初の通り道なら、まだつながっていない層を直しに 2 へ戻る。それ以外なら、失敗が示す足りない振る舞いを内側に 1 件だけ足して、内側のループへ戻る。
   - 緑: 受け入れの観点をかける（`accept.md`。`FINDINGS` なら、足した 1 件を持って内側のループへ戻る）。
     `CLEAN`・`UNVERIFIED` なら、進行中のタグを外し、既定の実行で選ばれて通ることを確かめ、`[x]` にする。続けて `refactor.md` の外側の棚卸しを行う。
     タグを外した変更と、棚卸しで消したテストを `test` の 1 コミットにする。
4. **次のシナリオへ**（1 に戻る）。シナリオが尽きたら `accept.md` の C を行い、開き直したシナリオがあれば、その内側のループへ戻る。

## 止まる条件 / When to stop

どれかに当たったら、その場でループを抜けて報告する。避けて進めない。
- リストを書けない。最初が緑でない。作業と関係のない差分がある。
- 受け入れの観点: 起動できない、`STOPPED`、3 回目でも `FINDINGS`。
- 外側: 直しても振る舞いで落ちない（step や準備の問題が解けない）。スタックが用意できない。ポートが他のプロセスに使われている。走らせ方が 0 件を選ぶ。
  失敗が、どのシナリオにも無い振る舞いを求めている。同じシナリオで同じ失敗が続いて進まない。
- red: 出典が無い・読めない・実際と食い違う。直しても意図した理由で落ちない（前の項目や共通の仕組みですでに成り立っていると示せる場合を除く。`red.md` の 6）。
- green: テストが間違っていると判断した。大きな構造の変更が要る（`refactor` の type 2 を勧める）。1 つの責務に収まらない（最初の通り道を除く）。**既存のテストが落ち、リストに載っていない。**
- refactor: 振る舞いや期待値を変えないと直せない。バグを見つけた。
- コミット: 赤のまま。フックが落ちる。触っていないファイルを切り分けられない。
- 同じ項目で 2 周しても進まない。

## 抜けたら / After the loop

理由を問わず（回しきった・止まった のどちらでも）、順に行う。
1. **自分が起動したスタックを止める**（`tdd.md`「スタック」）。止めたことを報告に書く。
2. **触った範囲のスイートを（`slow` も）全体で走らせる。**
3. **二重ループなら、触った受け入れテストを、データを空にした状態から走らせ直す**（`tdd.stack` の `reset` のあとに起動し直し、`run_default`。終わったら止める）。
   進行中のタグが残っているシナリオは対象にしない。動かしたままのスタックでデータの残りに助けられていた取りこぼしを、ここで拾う。

赤なら、コミットを取り消さず、どの変更が原因かを報告して止まる（直すのは次の red の仕事）。

## 報告 / Report

冒頭に走らせ方の宣言を 1 行。二重ループならシナリオごと、内側は項目ごとに 1 行に詰める:
```
[A<n>] <シナリオ名>（最初の通り道ならそう書く）
  外側 red:  FAIL（<落ちた箇所>） / commit: <hash> <件名>
  [<i>/<m>] <振る舞い>
    red:      <テスト名> → FAIL（<理由>） / 出典: <どこから>
    green:    <触ったファイル> → PASS
    commit:   <hash> <件名>
    refactor: <直した構造 or「直すものなし」>（commit があれば hash）
  外側:      FAIL → 足した項目: <…> / PASS → タグを外し、棚卸し: <消したテスト or なし>
  commit:    <hash> <件名>
```
単層なら `[A<n>]` の行を省き、項目のブロックだけを並べる。最後に必ず:
```
完了: シナリオ <n> 本・内側 <m> 件 / 残り: シナリオ <n'> 本・内側 <m'> 件（止まった項目が [~] のままか [ ] に戻したか）
コミット: <hash と件名>（commit: never なら、コミットの案）
全体の実行: <抜けたあとの全体の実行と、空のデータからの受け入れテストのコマンドと結果>
スタック: 停止済み
止まった理由: <止まる条件のどれか。回しきったなら「リストが尽きた」>
```
