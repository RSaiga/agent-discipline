# red — 落ちるテストを 1 本だけ書く / Write one failing test

実装はしない。 / Do not implement.

1. **リストから 1 件を決める。** 未着手 `[ ]` を上から 1 件取り、`[~]` にする（書けなければ `tdd.md` のとおり止まる）。
   全部終わっていれば「完了」と伝えて止まる。新しいテストをひねり出さない。
   二重ループのリストでは、進行中の `[~]` のシナリオの内側から取る。進行中のシナリオが無い、その内側が尽きている、
   または最初の通り道（内側を持たない）なら、red は書かない。`ad-accept`（最初の通り道なら `ad-green`）を案内して止まる。
   Take the first `[ ]` item and mark it `[~]`. In a double-loop list, take it from the scenario in progress; with none, point at `ad-accept`.
2. **出典を開いて、期待値を確かめる。** 項目の出典を実際に見て値を読む。リストの出典が実際と食い違えば、書き換えずに報告して止まる。
3. **置き場所とお手本を決める。** `tdd.tests` の置き場所に置き、お手本と隣のテストの書き方（名前、準備、アサーション）に倣う。
   テストの名前で振る舞いを語る。
4. **テストだけを書く。** 1 本に 1 つの振る舞い。コンパイルが通らない（まだ無い関数を呼ぶ）のも正しい red。
   stub は、その言語で red が見えないときだけ、空の最小限で作る。
   - `[change]`: 新しく書かず、既存のテストの期待値を承認された新しい仕様に書き換える。古い実装のせいで落ちるのが正しい red。
   - `[remove]`: 既存のテストを消す。落とすテストは無いので、5・6 は「同じファイルの残りが緑のまま」の確認に置き換える。コードは消さない（green の仕事）。
   Write only the test. A compile error is a valid red. `[change]` rewrites an existing expectation; `[remove]` deletes the test only.
5. **書いたテスト 1 本だけを走らせ、落ちることを見る**（`one`。型の確認で red を見る項目なら、その確認を走らせる）。
6. **落ちた理由が意図どおりか確かめる。** 書き間違い・準備の誤り・import の誤りで落ちているのは red ではない。テストを直して走らせ直す。
   Confirm it fails for the intended reason.
7. **止まる。** 報告し（出典と残りの件数を含める）、次は green と伝える。

**しないこと / Never:** 実装、1 本に複数の振る舞い、テストを緑にすること、出典の無いアサーション、リストへの項目の追加。
