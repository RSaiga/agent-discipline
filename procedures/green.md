# green — 落ちているテストを最小の実装で通す / Make the failing test pass

リファクタはしない。テストは変えない。 / No refactoring. Never edit the test.

1. **落ちているテストがあることを確かめる。** 直前の red が同じ作業ツリーで赤を報告していれば、その結果を使う。
   全部緑なら、書くものは無い。何が起きているかを報告して止まる。
2. **いちばん簡単な実装で通す。** きれいでなくてよい。
   - そのテストだけなら固定値で通るなら、固定値で通す（Fake It）。前の固定値がこのテストで通らなくなったときに初めて、一般化する（Triangulate）。
   - テストが求めていない処理・エラーの扱い・設定・抽象を足さない。次の振る舞いを先取りしない。
   - `[remove]`: 廃止する振る舞いのコードと、それで使われなくなったコードを消す。残りのテストが緑なら green。
   Pass it the simplest way; fake it until the next test forces generality.
3. **止まる場合:**
   - 通すのに大きな構造の変更が要る → 実装せずに、何がその変更を難しくしているかを報告して止まる（先に構造を整えるかはユーザーが決める）。
   - 変更が 1 つの責務に収まらない → その項目は大きすぎる。小さな例への割り方を提案して止まる（リストは書き換えない）。
   - テストの側が間違っていると判断した → 直さずに止まる（red のやり直しになる）。
4. **テストを走らせる**（`tdd.md`「どこまで走らせるか」の green）。
   **既存のテストが落ちたら、直さずに止まる。** リストの `[change]`・`[remove]` に載っていない、古い振る舞いを確かめるテストが落ちたなら、
   どのテストが新しい仕様と食い違うかを報告する。リストに足すかはユーザーが決める。
   If an existing test breaks and the list does not cover it, stop and report — never rewrite it.
5. **項目を `[x]` にする。** 新しく要る振る舞いに気づいたら、足さずに報告する。
6. **止まる。** 報告し、気づいたリファクタの候補は**やらずに**挙げる。次は refactor と伝える。

**しないこと / Never:** リファクタ・名前の変更・関数の切り出し、テストの書き換え、求められていない処理の追加。
