# refactor-only — TDD の外で構造を直す / Restructure outside TDD

振る舞いを変えない。テストの期待値を変えない。テストを足さない。 / No behavior change; assertions untouched; no new tests.
直してよいのは、既存のテストが守っている場所だけ。 / Touch only what existing tests guard.

1. **対象を決める。** 呼び出しの指定に従う（`review.md`「対象を決める」と同じ）: 無ければ作業中の変更、ブランチ名やコミットの範囲ならその差分、
   ファイルやフォルダならそのコード全体。
2. **匂いを挙げる。** `lenses/structure.md` を、`lenses.structure.catalog` と `tdd.rules` の規約に照らして実行する（読むだけ）。
   挙げた匂いの数と場所を書く。直すものが無ければ、無いと言って止まる。リファクタをひねり出さない。
3. **最初が緑であることを確かめる。** `tdd.suites` の `fast` のスイートを全体で走らせる。`tdd.known_failures` に名前のある失敗だけを除き、
   ほかが落ちていれば、何が落ちているかを報告して止まる。`tdd.suites` が無ければ、振る舞いを確かめる手段が無いので止まる。
4. **守っているテストを確かめる。** 匂いごとに、その場所を通るテストを検索で探す（呼び出し・名前・境界のテスト）。見つからない匂いは直さず、
   「テストで守られていない」として報告に残す（足すべきテストの案を 1 行で書く）。
5. **1 つずつ直す**（`refactor.md` の 4〜6 と同じ規律）。直すたびに、その手が触った範囲のテストを走らせる。
   アサーションか期待値を変えないと緑にならない、振る舞いが変わる、バグを見つけた → 直さずに止まって報告する。
6. **最後に緑を確かめる。** `fast` のスイートを全体で、`slow` のスイートは触ったパスだけ走らせる。
7. **コミット** — `commit.md`。種類は `refactor`。匂いごとにコミットを分けてよい。`commit: never` ならコミットの案を残す。
8. **報告する。** 直した匂い（場所・手当て・走らせたテスト）、直さなかった匂いと理由（テストで守られていない、振る舞いが変わる）、コミット。

**しないこと / Never:** テストの追加・削除・期待値の変更、機能の追加、「ついで」の修正、テストで守られていない場所の変更、まとめて直して最後に 1 回だけ走らせること。
