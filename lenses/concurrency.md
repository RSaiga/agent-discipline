# concurrency — 並行の観点 / Concurrency lens

変更を、下の汎用の項目と、プロジェクトが足した項目（`profile.md` の `lenses.concurrency.catalog`。無くてよい）に照らして読み、
同時に動くもの（要求、ワーカー、インスタンス、テスト）の重なりで破れる箇所を指摘する。構造の問題は扱わない。
Read the change against the generic items below and the project's additions, and point out what breaks when things run at the same time.

## 項目 / Items

番号は指摘の根拠に使う。プロジェクトの項目があれば、それを先に疑う。 / Cite the id; suspect the project's items first.

| 番号 | 項目 | 疑うところ |
|---|---|---|
| CON-1 | 確かめてから実行するまでの競合 | 読んで判断してから書くまでのあいだに、別の要求が割り込めるか（`await`・I/O・ロックの外） |
| CON-2 | 冪等性 | Webhook・リトライ・二度押しで、同じ要求が 2 回来たときに 2 回効かないか |
| CON-3 | トランザクションの範囲と分離 | 一緒に成り立つべき書き込みが、別々のトランザクションや範囲の外にないか。分離のレベルで足りるか |
| CON-4 | 複数のインスタンス | プロセス内のキャッシュ・定期実行・ローカルのファイルが、インスタンスが増えると食い違わないか |
| CON-5 | プロセス全体で共有する状態 | モジュールの変数・シングルトン・環境変数を、要求ごとの値の置き場にしていないか |
| CON-6 | 途中の中断 | 非同期の処理が途中で止まったとき、半端な状態が残らないか |
| CON-7 | 後勝ち | 同時の更新で、片方の変更が黙って消えないか（読み込んだ版を確かめずに上書き） |
| CON-8 | テストの並列実行 | テストが共有するもの（DB の行、環境変数、ファイル、時刻）で、並べて走らせると結果が変わらないか |

言語の安全（メモリ安全、型）は、論理の競合を防がない。 / Memory and type safety do not prevent logical races.

## 読み方 / How to read

- **変更そのものは差分から読む。** 追跡外の新しいファイルも対象。
- **共有されるものを先に洗い出す。** 変更が読み書きする、要求をまたいで残るもの（DB の行、モジュールの変数、キャッシュ、ファイル、外部のサービス）。
  それぞれについて、読む場所・書く場所・そのあいだにある中断点（`await`、I/O、別のトランザクション）を見る。
- たどるのに要るだけ検索してよい。検索は、確かめたいことを洗い出してからまとめて出す。
- **確かめずに判断しない。** 「ロックしている」「1 つのトランザクションだ」と見なすなら、その場所を実際に見る。

## 判定 / How to judge

- **確信度「高」には、壊れる順番を書く。** 2 つの要求（か処理）の手順を並べ、どこで割り込むと何が起きるかを示す。書けなければ「中」か「低」にする。
  例: 要求 A が未読を読む → 要求 B が未読を読む → A が数を 1 増やす → B が数を 1 増やす → 1 冊なのに 2 と数える。
- **「高」は、壊れる理由が「同時に動くものの重なり」か「要求をまたいで残る共有の状態」のときだけ。**
  共有の状態は、モジュールの変数・プロセス内のキャッシュ・シングルトンなど（1 つずつ順に来ても、前の要求の値が次の要求に漏れるなら「高」）。
  ある口が数を足し忘れている、のような処理の抜けは、時刻にも共有の状態にもよらず壊れるので並行の問題ではない。「中」か「低」で触れるにとどめる。
  High only when the cause is overlap in time or state that outlives a request (module variables, in-process caches); a missing step in one path is not a concurrency finding.
- **実行環境が 1 つに並べているなら指摘しない。** たとえば同期の処理だけで、中断点が無いもの。並べている根拠を確かめたうえで。
- **出典の無い要件を作らない。** 言語パックの例は直し方の見本で、このプロジェクトの要件ではない。
- **誤検出を出さない。**

## 指摘の形 / Finding format

```
### [CON-<番号> <項目>] — <file>:<line>  (確信度: 高/中/低)
- 何が問題か: <1〜2 行>
- 壊れる順番: <高のときは必須。手順を → でつなぐ>
- 提案する手当て: <具体的に>
```

最後の行は `## LENS CLEAN` か `## LENS FINDINGS <件数>`（`discipline.md`「観点の約束」）。
