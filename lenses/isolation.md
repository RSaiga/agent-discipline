# isolation — 独立の観点 / Isolation lens

変更を、下の汎用の項目と、プロジェクトが足した項目（`profile.md` の `lenses.isolation.catalog`。無くてよい）に照らして読み、
**データが混ざる**箇所を指摘する。混ざる相手は 2 つ: 別のテナント（組織・利用者）のデータと、別のテストのデータ。構造の問題は扱わない。
Read the change against the generic items below and the project's additions, and point out where data mixes:
another tenant's data in production, or another test's data in the test suite.

## 項目 / Items

番号は指摘の根拠に使う。プロジェクトの項目があれば、それを先に疑う。 / Cite the id; suspect the project's items first.

| 番号 | 項目 | 疑うところ |
|---|---|---|
| ISO-1 | テナントでの絞り込み | 読む・書く・消す処理が、ID だけで探していないか。呼び出した主体のテナントで絞っているか |
| ISO-2 | テナントをまたぐ集計・一覧 | 件数・合計・一覧・検索・エクスポートが、全テナントの行を数えたり返したりしないか |
| ISO-3 | キーにテナントが入っているか | キャッシュ・セッション・一時ファイル・ストレージの置き場所のキーに、テナントや利用者が入っているか |
| ISO-4 | 非同期の処理の文脈 | ジョブ・イベント・Webhook・定期実行が、起動したときのテナントを引き継いでいるか（全テナントに効かないか） |
| ISO-5 | 存在を漏らさない | 別のテナントの資源を、「無い」と同じ応答（404 など）で返しているか。権限が無い、と答えて存在を知らせていないか |
| ISO-6 | テストのデータの独立 | テストが、ほかのテストが作った行・ID・順番に頼っていないか。作ったものを片付けるか、毎回空から始めるか |
| ISO-7 | テストが変えて戻さない共有の状態 | 環境変数・時刻・モジュールの変数・ファイル・シングルトンを変えたまま、次のテストに渡していないか |
| ISO-8 | テストの並列実行の取り合い | 同じ DB の行・ポート・ファイル名・固定の ID を、並べて走るテストが取り合わないか |

security の SEC-2（テナント分離）と concurrency の CON-8（テストの並列実行）は、この観点を使っているときはこちらで扱う。

## 読み方 / How to read

- **変更そのものは差分から読む。** 追跡外の新しいファイル（新しいテストなど）も対象。
- **テナントの流れをたどる。** 入口で決まった主体（ログインした利用者、組織）が、クエリ・キャッシュのキー・ジョブの引数まで届いているか。
  共通の仕組み（ミドルウェア、リポジトリの基底、行のレベルの制約）が絞っていると見なすなら、その場所を実際に見る。
- **テストは、共有されるものを先に洗い出す。** テストが読み書きする DB の行・環境変数・時刻・ファイル・モジュールの変数と、その準備と片付けを見る。
- たどるのに要るだけ検索してよい。検索は、確かめたいことを洗い出してからまとめて出す。

## 判定 / How to judge

- **確信度「高」には、混ざる具体的な手順を書く。** テナントなら「テナント A の利用者が、テナント B の ID を指定すると B の行が返る」。
  テストなら「テスト X が先に走ると、テスト Y が X の作った行を数えて落ちる」（順番か並列で結果が変わることを示す）。書けなければ「中」か「低」。
- **「高」は、データが実際に混ざるときだけ。** 絞り込みの書き方が好みと違う、片付けが冗長、などは「中」か「低」。
- **共通の仕組みや実行環境が防いでいるなら指摘しない。** 防いでいる場所（行のレベルの制約、テストごとのトランザクションの巻き戻し、テストごとの DB）を確かめたうえで。
- **出典の無い要件を作らない。** テナントの概念が無いプロジェクトでは、ISO-1〜5 は当てはめない。
- **誤検出を出さない。**

## 指摘の形 / Finding format

```
### [ISO-<番号> <項目>] — <file>:<line>  (確信度: 高/中/低)
- 何が問題か: <1〜2 行>
- 混ざる手順: <高のときは必須。手順を → でつなぐ>
- 提案する手当て: <具体的に>
```

最後の行は `## LENS CLEAN` か `## LENS FINDINGS <件数>`（`discipline.md`「観点の約束」）。
